# Requirements Document

## Introduction

Palmier Pro for Linux currently contains well-tested building blocks (domain core, media engine, GPU layer, services, view models) but no assembled product: the application shows a placeholder window, no media can be imported, nothing plays back, nothing exports, and the agent endpoint speaks a non-standard protocol. This feature turns the existing components into a genuinely usable end-to-end editor: launch the GUI with mounted panels, import media, build a timeline, play it back with audio, save and re-open the project, and export a real file with GPU-accelerated encoding and CPU fallback. It also brings the agent/MCP surface up to the Model Context Protocol standard, adds a secure opt-in remote access path, makes the generative and natural-language backends pluggable behind an offline-capable default, and captures feature parity with the upstream macOS product plus the porting of recent upstream changes.

### Scope decision

All 16 requirements form a single deliverable with equal priority: the plan is not split into a "usable slice first, parity later" phasing. Upstream feature parity (Requirement 13) and the porting of recent upstream changes (Requirement 14) are in scope alongside the runnable-editor work.

### Codebase audit findings (verified against source)

Each item the user reported was confirmed in the repository at commit `c686206` on branch `feat/linux-port-gpu`:

| # | Reported gap | Verified state |
|---|---|---|
| 1 | Export not connected | `media/ExportEngine.{hpp,cpp}` exists and is tested, but `ApplicationComposition` never constructs it; `ToolRegistry`'s `timeline.export` tool has no hook and returns `Unsupported` ("no export engine is configured"). |
| 2 | No media-import tool | `media/ImportValidation.*`, `media/MediaProbe.*` and `core/MediaManager` exist; no tool named `media.import` exists anywhere in `src/` or `tests/`. `MediaBrowserViewModel::importMedia` exists but is not reachable from the app or the tool surface. |
| 3 | No project/track/asset tools | `ToolRegistry` registers exactly `timeline.read`, `add_clip`, `delete_clip`, `move_clip`, `trim_clip`, `split_clip`, `reorder_clips`, `add_effect`, `add_transition`, `generation.generate`, `timeline.export`. There is no track-creation, asset-registration, project-create, or project-open tool. |
| 4 | GUI not mounted | `ui/MainWindow.cpp` builds a `QLabel` placeholder and a File menu whose only action is Quit; `TimelineViewModel`, `PreviewController`, `InspectorViewModel`, `MediaBrowserViewModel`, `AgentChatViewModel` and their `*Panel` surfaces are never instantiated by `MainWindow` or `ApplicationComposition`. `MainWindow` takes no composition reference. |
| 5 | Save/Open not wired | `services/ProjectSaveService` (atomic save) and `services/ProjectStore::loadProjectFromFile` exist and are tested; no menu action, dialog, or window state references them. |
| 6 | Playback not wired | `media/MediaDecoder`, `gpu/Compositor`, `ui/PreviewController` all exist independently; nothing constructs a decoder-backed `ClipFrameProvider`, and `ApplicationComposition` exposes no compositor, decoder, or preview controller. |
| 7 | Audio incomplete | `media/AudioGraph` provides mixing/resampling only. `MediaDecoder` has no audio-frame API (its header defers audio decode to a future task), `MediaEncoder` has no audio stream/encode API, `ExportEngine` contains no audio path, and there is no audio output device abstraction. |
| 8 | GPU encoding disabled | `PALMIER_ENABLE_NVENC/QSV/VAAPI` default to `ON` in `cmake/PalmierOptions.cmake`, but `.github/workflows/ci.yml` configures with `-DPALMIER_ENABLE_NVENC=OFF -DPALMIER_ENABLE_QSV=OFF`, so `PALMIER_HAVE_NVENC`/`PALMIER_HAVE_QSV` are undefined and `CodecBridge` reports those backends unavailable. `MediaEncoder` names `h264_nvenc`/`hevc_nvenc`/`*_vaapi`/`*_qsv` encoders but no NVIDIA validation exists. |
| 9 | AI generation is a stub | `ApplicationComposition` installs `OfflineGenerativeBackend`, whose `submit`/`poll`/`fetchResult` return `Unsupported`. No hosted-service or BYOK-provider client implementation exists. |
| 10 | Agent reasoning unconfigured | `makeUnconfiguredInterpreter()` returns `FailedPrecondition` for every utterance, so `AgentOrchestrator` cannot map natural language to tools. |
| 11 | Non-standard MCP | `McpServer::dispatch` accepts POST `/mcp` and delegates the raw body to `McpToolExecutor::execute`, which reads `{name, arguments}` (or `params.name`) and answers `{"ok":…, "result"/"error":…}`. There is no `initialize`, `tools/list`, or `tools/call` method dispatch and no JSON-RPC 2.0 envelope on success paths. |
| 12 | Loopback only | `McpServer::start` rejects any non-loopback host via `isLoopbackHost`, and there is no authentication, TLS, or origin check. |

Additional gaps found during the audit, not in the original list:

- `McpToolExecutor` holds a single `TimelineEngine*`; there is no project-session concept, so "open a different project" has no representation.
- No transitions/effects UI exists, and `add_transition` is implemented by a registry-local command rather than a core `EditCommand`.
- `tests/palmier_placeholder_property_test.cpp` remains a placeholder property test.
- No end-to-end (import → edit → play → save → open → export) test exists that runs the assembled application; `tests/media_import_edit_export_integration_test.cpp` exercises components directly with synthetic frames.

### Upstream reference

The upstream product was identified as [palmier-io/palmier-pro](https://github.com/palmier-io/palmier-pro) with high confidence: this repository's `CMakeLists.txt` sets `HOMEPAGE_URL "https://github.com/palmier-io/palmier-pro"`, and the upstream README describes the same architecture (GPLv3 open editor plus MCP server and agent chat, closed generative service, MCP endpoint at `http://127.0.0.1:19789/mcp`). Upstream is a Swift/SwiftUI macOS application (macOS 26, Apple Silicon) organised into `Sources/PalmierPro/{Timeline,Editor,Preview,Export,Generation,Transcription,Audio,Compositing,Inspector,MediaPanel,Agent,Search,Settings,Account,Telemetry,…}`, with an agent tool surface spanning clips, timeline, texts, captions, transcription, color, effects, denoise, multicam, organize, layout, media, import, export, generate, projects, project settings, search, sync, beats, capture-frame and words. Upstream serves standard MCP over HTTP with per-session `Server` instances, `initialize` detection, session-id headers, SSE streams, `tools/list_changed` notifications, localhost origin validation and an OAuth protected-resource document. Requirements 13 and 14 depend on this identification; if the user names a different upstream, those two requirements must be revisited.

## Glossary

- **Editor_Shell**: The Qt 6 main window and its docked panel layout (`ui/MainWindow`), which hosts the timeline, preview, inspector, media browser and agent panels.
- **Composition_Root**: `app/ApplicationComposition`, the single object graph that constructs and connects all editor components.
- **Project_Session**: The service that owns the currently open project — its `TimelineEngine`, its on-disk location, and its modified/unmodified state.
- **Media_Import_Service**: The component that probes, validates and registers a media file into the project media library.
- **Playback_Engine**: The composed decode → composite → present pipeline driving the preview surface (`media/MediaDecoder` + `gpu/Compositor` + `ui/PreviewController`).
- **Audio_Engine**: The composed audio decode → mix → output pipeline (`media/AudioGraph` plus audio decode and an audio output sink).
- **Export_Coordinator**: The component that validates an export request, runs `media/ExportEngine`, muxes audio and video, and reports progress and completion.
- **Encoder_Selector**: The runtime logic that chooses a hardware or software encoder (`gpu/CodecBridge` + `media/MediaEncoder`).
- **Tool_Surface**: The single registry of editor tools (`services/ToolRegistry`) shared by the GUI, the MCP endpoint and the in-app agent.
- **MCP_Endpoint**: The HTTP transport that serves the Model Context Protocol (`services/McpServer`).
- **MCP_Protocol_Handler**: The JSON-RPC 2.0 method dispatcher for `initialize`, `notifications/initialized`, `tools/list` and `tools/call`.
- **Remote_Access_Gate**: The admission control for non-loopback MCP connections (bind address policy, bearer-token authentication, TLS, origin checks).
- **Agent_Interpreter**: The pluggable natural-language-to-tool-intent component consumed by `services/AgentOrchestrator`.
- **Generative_Backend**: A pluggable implementation of `services::IGenerativeBackend` (hosted Palmier service, a BYOK provider such as Gemini/Veo, or the offline stub).
- **Parity_Report**: The checked-in document that maps upstream features to their Linux status.
- **Port_Backlog**: The checked-in, prioritised list of upstream changes selected for porting.
- **Verification_Suite**: The CTest-registered GoogleTest and RapidCheck tests plus the CI jobs that run them.
- **L4_Validation_Job**: The CI or operator-run job that exercises hardware encode on an NVIDIA L4 GPU.
- **Offline_Mode**: Operation with no reachable network and no authenticated account.

## Requirements

### Requirement 1: Assembled Application Shell

**User Story:** As a video editor on Linux, I want the application to open a real editing workspace, so that I can see and use the timeline, preview, inspector, media browser and agent panels.

#### Acceptance Criteria

1. WHEN the application starts on a host meeting the documented minimum specification, THE Composition_Root SHALL construct exactly one instance each of the Project_Session, Media_Import_Service, Playback_Engine, Audio_Engine, Export_Coordinator and Tool_Surface, and SHALL expose each of them through a public accessor that returns a non-null reference to that same instance for the lifetime of the application.
2. WHEN the Editor_Shell is shown, THE Editor_Shell SHALL display all five panels — timeline, preview, inspector, media browser and agent chat — simultaneously, each bound to exactly one view model instance obtained from the Composition_Root, with no additional user action required to make any panel visible.
3. WHEN the Editor_Shell is shown, THE Editor_Shell SHALL present a menu bar containing the menus File, Edit, Playback, Export and Help in that order, each containing at least one activatable action.
4. WHILE the Editor_Shell window is at any size from 1024x640 up to 7680x4320 logical pixels, THE Editor_Shell SHALL keep every one of the five panels reachable — visible, or selectable in at most one user action through a docked tab or menu action — with each visible panel occupying at least 80x60 logical pixels, and SHALL clamp any resize request below 1024x640 logical pixels to that minimum.
5. WHEN the application is started from a cold process launch on a host meeting the documented minimum specification, THE Editor_Shell SHALL become visible with all five panels rendered no later than 15 seconds after process start.
6. IF the GPU probe reports that no compatible device is available, THEN THE Editor_Shell SHALL display the software-fallback notice text returned by `Composition_Root::gpuUnavailableNotice` in the status bar, keep that notice visible until the user dismisses it or the application exits, and continue to open all five panels.
7. WHEN a user triggers an edit through any of the five panels, THE Editor_Shell SHALL submit that edit to the Tool_Surface as a named tool invocation with arguments instead of mutating project state directly, so that the same tool name and arguments submitted through the GUI, the MCP_Endpoint or the in-app agent yield project state that compares equal in track order, clip order, clip source ranges, effects and transitions.
8. WHEN a user activates Edit > Undo while the undo history contains at least one applied edit, THE Project_Session SHALL restore, within 1 second, the project state that existed immediately before the most recent applied edit, equal in track order, clip order, clip source ranges, effects and transitions.
9. IF the Composition_Root cannot construct any component named in criterion 1 during startup, THEN THE Composition_Root SHALL abort startup without showing the Editor_Shell and SHALL report an error naming the component that failed to construct and the failure reason.
10. WHEN the application starts and no project path is supplied, THE Project_Session SHALL make an empty project using the documented default frame rate, canvas resolution and color space the current project, so that all five panels render that empty project's state without an error indication.
11. IF the undo history is empty, THEN THE Editor_Shell SHALL present the Edit > Undo action in a disabled state and SHALL leave the project state unchanged.

### Requirement 2: Media Import

**User Story:** As an editor, I want to import media files from the GUI or from an agent, so that footage becomes available for placement on the timeline.

#### Acceptance Criteria

1. WHEN a user selects a single media file through the media browser import action, and the media engine can read the file's container and decode at least one of its streams, THE Media_Import_Service SHALL probe the file, validate it, register exactly one asset in the media library of the currently open project, and display that asset as a row in the media browser panel within 5 seconds for files up to 2 GB in size.
2. WHEN an agent invokes the `media.import` tool with an absolute path to a file the media engine can read and decode, THE Media_Import_Service SHALL register the asset and return the assigned asset identifier, the resolved absolute source path, the container format name, the duration in milliseconds, and, for an asset carrying at least one decodable video stream, the pixel resolution and the frame rate in frames per second, reporting resolution and frame rate as absent for an asset with no decodable video stream.
3. IF the media engine does not recognise an import target's container, or every stream the container carries uses a codec the media engine cannot decode, THEN THE Media_Import_Service SHALL leave the media library entry count and contents unchanged and return an error that names the container format and the codecs that were rejected.
4. IF an import target path is empty, names a file that does not exist, names a file that cannot be opened or read, or names a file whose decodable stream fails to decode, THEN THE Media_Import_Service SHALL leave the media library entry count and contents unchanged and return an error that names the file path and states which of these four conditions occurred.
5. WHEN an import is requested for a path that resolves to the same absolute filesystem location as an asset already registered in the currently open project, including when the two requests arrive from the media browser import action and the `media.import` tool within one session, THE Media_Import_Service SHALL return the identifier of the existing asset, add no new entry, and keep exactly one media library entry for that location.
6. FOR ALL sequences of import requests, THE Media_Import_Service SHALL produce a media library whose entry count equals the number of distinct absolute filesystem locations imported successfully, and SHALL leave that entry count unchanged for every rejected and every duplicate request (invariant property).
7. IF an import is requested while the Project_Session has no open project, THEN THE Media_Import_Service SHALL register no asset and return an error stating that no project is open.
8. IF probing and validation of an import target do not complete within 30 seconds, THEN THE Media_Import_Service SHALL abandon that import, leave the media library entry count and contents unchanged, and return an error that names the file path and indicates that the import exceeded the time limit.
9. WHILE an import of a target path is in progress, THE Media_Import_Service SHALL report that import as pending and SHALL expose no media library entry and no media browser row for that path until probing, validation and registration have all succeeded.

### Requirement 3: Headless Project and Timeline Construction

**User Story:** As an agent author, I want tools that create projects, tracks and clips, so that an external agent can build a complete timeline without the GUI.

#### Acceptance Criteria

1. THE Tool_Surface SHALL expose the tools `project.create`, `project.open`, `project.save`, `project.info`, `media.import`, `media.list`, `timeline.add_track`, `timeline.remove_track` and `timeline.export` in addition to the existing timeline editing tools, and SHALL make each of them retrievable under its exact listed name through the single registry shared by the GUI, the MCP_Endpoint and the in-app agent.
2. WHEN `project.create` is invoked with a project name of 1 to 128 characters, a frame rate between 1 and 240 frames per second, a canvas resolution between 16x16 and 7680x4320 pixels, and a color space drawn from the set the domain core exposes, THE Project_Session SHALL create a project carrying exactly those settings, make it the current project, report it as unmodified with no known on-disk location, and return a project identifier unique within the session.
3. WHEN `timeline.add_track` is invoked with a track kind of `video` or `audio` while the current project holds fewer than 64 tracks of that kind, THE Project_Session SHALL append the new track after the last existing track of that kind, leave all existing tracks and clips unchanged, and return a track identifier unique within the project.
4. WHEN `project.open` is invoked with the path of a `.palmier` document that deserializes successfully, THE Project_Session SHALL replace the current project with the loaded project, make it the current project, report it as unmodified with its on-disk location known, and return the loaded project's identifier, track count and clip count.
5. IF any tool other than `project.create` and `project.open` is invoked while no project is current, THEN THE Project_Session SHALL leave all state unchanged, create no edit command, and return an error stating that no project is open.
6. WHEN a headless client performs the sequence `project.create`, `timeline.add_track`, `media.import`, `timeline.add_clip`, `project.save`, `timeline.export` with arguments each tool accepts, THE Tool_Surface SHALL return a success result for every call and SHALL produce a file at the requested export path that the media engine can probe and decode.
7. FOR ALL sequences of at most 64 successful `timeline.add_track` calls and at most 500 successful `timeline.add_clip` calls containing no removal calls, `project.info` SHALL report a track count equal to the number of successful `timeline.add_track` calls and a clip count equal to the number of successful `timeline.add_clip` calls (invariant property).
8. IF `project.create`, `timeline.add_track` or `timeline.remove_track` is invoked with an argument outside its accepted values — a project name of 0 characters or more than 128 characters, a frame rate below 1 or above 240 frames per second, a canvas width outside 16 to 7680 pixels or height outside 16 to 4320 pixels, a color space outside the set the domain core exposes, a track kind other than `video` or `audio`, a request that would exceed 64 tracks of one kind, or a track identifier not present in the current project — THEN THE Project_Session SHALL leave the project unchanged, create no edit command, and return an error naming the rejected argument.
9. IF `project.open` is invoked with a path that is missing, unreadable, not a valid `.palmier` document, or written with an unsupported schema version, THEN THE Project_Session SHALL keep the project that was current before the call unchanged, including its modified state, and return an error naming the path and the failure reason.
10. WHEN `timeline.remove_track` is invoked with a track identifier present in the current project, THE Project_Session SHALL remove that track and every clip on it, preserve the relative order of the remaining tracks, and return the resulting track count and clip count.

### Requirement 4: Project Save and Open from the GUI

**User Story:** As an editor, I want to save my project and open it later, so that my work survives closing the application.

#### Acceptance Criteria

1. WHEN a user activates File > Save while the Project_Session holds a recorded document path (a `.palmier` path established by a previous successful save or open in the current session), THE Project_Session SHALL write the complete project to that recorded path through `ProjectSaveService` within 5 seconds for projects within the bounds stated in criterion 7, and SHALL display a confirmation naming the written path.
2. WHEN a user activates File > Save while the Project_Session holds no recorded document path, THE Editor_Shell SHALL present a destination prompt that defaults to the `.palmier` extension, and upon the user confirming a destination SHALL perform the write and confirmation described in criterion 1 and record the confirmed path as the project's document path.
3. WHEN a user activates File > Open and confirms a selected `.palmier` document that loads successfully, THE Project_Session SHALL replace the current project with the loaded project, record the selected path as the project's document path, report the project as unmodified, and refresh the timeline, preview, inspector and media browser panels to the loaded state within 10 seconds for documents within the bounds stated in criterion 7.
4. IF a save fails because the destination is unwritable, the permissions are insufficient, or the volume has insufficient space, THEN THE Project_Session SHALL preserve any previously saved file at that path byte-for-byte, leave the in-memory project and its modified state unchanged, and display an error naming the destination path and stating that the save did not complete.
5. IF a user attempts to close the Editor_Shell or open another project while the current project has unsaved modifications, THEN THE Editor_Shell SHALL present a prompt offering exactly three options — save, discard, cancel — SHALL make no state change and write no file while the prompt is displayed, and SHALL then apply exactly one outcome without further prompting: for save, perform the write of criterion 1 or criterion 2 and continue the pending close or open only if that write reports success, otherwise keep the current project open with its modifications and undo history intact; for discard, continue the pending close or open without writing and leave any previously saved file byte-for-byte unchanged; for cancel, abandon the pending close or open and leave the current project, its modified state and its undo history unchanged.
6. WHEN a save completes successfully, THE Project_Session SHALL report the project as unmodified through its public accessor until the next edit applied through the Tool_Surface.
7. FOR ALL projects that can be constructed through the Tool_Surface with 1 to 20 tracks, 0 to 200 clips per track, 0 to 10 effects per clip, 0 to 50 transitions, 0 to 200 registered assets and names of 0 to 255 characters, saving then opening SHALL produce a project equal to the original in identifier, name, frame rate, canvas, color space, track order, clip order, clip source ranges, effects, transitions and asset references (round-trip property).
8. FOR ALL projects within the bounds stated in criterion 7, saving a loaded project SHALL produce a document that deserializes to the same project as the first save (idempotence property).
9. IF a user dismisses the destination prompt of criterion 2 or the File > Open file selection without confirming a path, THEN THE Editor_Shell SHALL write no file, load no project, leave the current project, its document path and its modified state unchanged, and report no error.
10. IF a File > Open target is missing, unreadable, not a valid `.palmier` document, or declares an unsupported schema version, THEN THE Project_Session SHALL keep the current project, its document path, its modified state and all four refreshed panels unchanged, and display an error naming the selected file and the failure reason.


### Requirement 5: Playback Pipeline

**User Story:** As an editor, I want to play my timeline in the preview panel, so that I can judge my edit before exporting.

#### Acceptance Criteria

1. WHILE the playhead is at a timeline position covered by a video clip, THE Playback_Engine SHALL present a composited frame whose per-channel pixel values match, within a tolerance of 2 of 255 levels, the frame that the `MediaDecoder`-backed clip frame provider decodes for that clip's corresponding source position.
2. WHEN a user activates the play transport control on a timeline whose duration is greater than zero, THE Playback_Engine SHALL present composited frames at the project canvas resolution at a mean presentation rate, measured over each rolling 1-second window of playback, of at least the lesser of the project frame rate and 24 frames per second and no more than the project frame rate plus 1 frame per second, dropping no more than 5 percent of the planned frames over the whole playback run.
3. WHILE playback is running and no seek is in progress, THE Playback_Engine SHALL advance the playhead so that each presented frame's timeline position is strictly greater than that of the previously presented frame, and SHALL update the timeline playhead indicator at least 10 times per second with a displayed position within 100 milliseconds of the presented frame position.
4. WHEN a user activates the pause transport control, THE Playback_Engine SHALL stop advancing the playhead within 100 milliseconds, retain the playhead at the position of the last presented frame, present that frame within 500 milliseconds, and report the playback state as paused.
5. IF the `MediaDecoder`-backed clip frame provider reports a decode failure for a source frame while playback is running, THEN THE Playback_Engine SHALL stop advancing the playhead within 100 milliseconds, keep the last successfully presented frame on the preview surface, report the playback state as paused, leave the project state unchanged, and display an error message that names the asset whose decode failed.
6. IF the GPU compositing path reports a failure at runtime, THEN THE Playback_Engine SHALL resume presenting frames through the software compositing path within 500 milliseconds, SHALL report the active compositing path as software through a public accessor for the remainder of the session, and SHALL display a notice in the Editor_Shell status bar stating that software compositing is in use.
7. FOR ALL timelines, playing from timeline position zero until playback halts SHALL yield a presented frame count plus a reported dropped frame count equal to `ExportEngine::plannedFrameCount` for the same timeline and frame rate, with strictly increasing presentation timestamps across the presented frames; for a timeline whose `plannedFrameCount` is zero, no frames SHALL be presented and the playback state SHALL remain reported as stopped (invariant property).
8. WHEN a user activates the stop transport control, THE Playback_Engine SHALL stop advancing the playhead within 100 milliseconds, set the playhead to timeline position zero, present the frame for position zero within 500 milliseconds, and report the playback state as stopped.
9. WHEN a user seeks to a timeline position, THE Playback_Engine SHALL clamp the requested position to the closed interval from zero to the timeline duration, present the frame for the clamped position within 500 milliseconds, and report the clamped position as the current playhead position, whether playback was running or halted when the seek was requested.
10. WHILE playback is running, WHEN the playhead reaches the timeline duration, THE Playback_Engine SHALL stop advancing the playhead within 100 milliseconds, keep the last presented frame on the preview surface, and report the playback state as stopped.

### Requirement 6: Audio Pipeline

**User Story:** As an editor, I want to hear my timeline during playback and hear it in the exported file, so that I can cut to dialogue and music.

#### Acceptance Criteria

1. WHEN an imported asset containing at least one audio stream is opened for playback or export, THE Audio_Engine SHALL decode that asset's audio stream into interleaved sample buffers, each buffer declaring a sample rate in the range 8,000 to 192,000 samples per second, a channel count in the range 1 to 8, and a presentation timestamp that is non-decreasing across consecutive buffers of the same stream.
2. WHEN playback is running, THE Audio_Engine SHALL mix every clip on an unmuted audio-bearing track at its clip gain (0.0 or greater, where 1.0 is unity) through `AudioGraph` into the Audio_Engine output format of 48,000 samples per second with 2 interleaved channels, and SHALL deliver the mixed samples to the system audio output with no dropout longer than 100 milliseconds.
3. WHILE playback is running, THE Audio_Engine SHALL keep the presented audio sample position within 40 milliseconds of the presented video frame position, measured at least once per second for the full duration of playback.
4. WHEN a user mutes or unmutes a track, or sets a clip gain to a value of 0.0 or greater, THE Audio_Engine SHALL apply that change to subsequently mixed samples within 200 milliseconds and SHALL leave the playhead position unchanged.
5. WHEN an export request includes audio, THE Export_Coordinator SHALL encode the mixed timeline audio at the Audio_Engine output format, mux it into the output file as exactly one audio stream alongside the video stream, and report in the export result that the output contains audio.
6. IF an asset placed on the timeline contains no audio stream, THEN THE Audio_Engine SHALL contribute zero-valued samples at the Audio_Engine output format for that asset's timeline range, continue mixing the remaining clips, and report no error.
7. IF the system audio output device is unavailable or cannot be opened, THEN THE Audio_Engine SHALL suppress audio output, allow the Playback_Engine to continue presenting video at the project frame rate, and display within 2 seconds a notice stating that audio output is unavailable, retaining that notice until an audio output device is opened successfully.
8. FOR ALL timelines, the mixed audio duration produced for export SHALL equal the timeline duration within one audio frame (one sample per channel at the Audio_Engine output sample rate), and every output sample value SHALL remain within the range [-1.0, 1.0] after clip gain is applied (invariant property).
9. IF decoding an audio buffer fails during playback, THEN THE Audio_Engine SHALL contribute silence for the remainder of that clip's timeline range, continue mixing the remaining clips, allow the Playback_Engine to continue presenting video, and display an error naming the failing asset.
10. IF audio encoding or muxing fails during an export that includes audio, THEN THE Export_Coordinator SHALL stop the export, remove the incomplete output file, leave the project state unchanged, and report an error identifying audio encoding or muxing as the failing stage.
11. IF an export request includes audio while the timeline contains no clip on an unmuted audio-bearing track, THEN THE Export_Coordinator SHALL write a silent audio stream spanning the full timeline duration and complete the export successfully.

### Requirement 7: Export Integration

**User Story:** As an editor, I want to export my finished timeline to a video file from the GUI or from an agent, so that I can deliver the result.

#### Acceptance Criteria

1. WHEN a user confirms an export in the export dialog with an output path of at most 4096 characters whose parent directory exists and is writable, a container format and video codec that the Encoder_Selector supports, a resolution between 128x128 and 3840x2160, a frame rate between 1 and 120 frames per second, and a video bit rate between 100 and 200000 kilobits per second, THE Export_Coordinator SHALL run `ExportEngine` with exactly those parameters and SHALL leave the project state unchanged, reporting the project as unmodified for every export outcome.
2. WHEN the `timeline.export` tool is invoked with an output path, container format, video codec, resolution, frame rate and bit rate meeting the constraints of criterion 1, THE Export_Coordinator SHALL perform the same export as criterion 1 and return the output path, the encoded frame count, the selected encoder name and a boolean stating whether hardware encode was used.
3. WHILE an export is running, THE Export_Coordinator SHALL report progress as a monotonically non-decreasing percentage in the range 0 to 100 at intervals of at most 1 second, and SHALL keep the Editor_Shell processing window events — move, resize, repaint and cancel activation — with no single unresponsive interval exceeding 200 milliseconds.
4. WHEN an export completes successfully, THE Export_Coordinator SHALL report final progress of 100 percent and the output location within 2 seconds of the last encoded frame, and SHALL produce a non-empty file that the media engine can probe and decode, whose decoded frame count equals `ExportEngine::plannedFrameCount` for the exported timeline and frame rate and whose reported duration differs from the timeline duration by at most one frame interval.
5. IF an export fails at any point after encoding begins, THEN THE Export_Coordinator SHALL stop encoding, delete the partially written output file within 5 seconds so that no file remains at the requested path, report the project as unmodified, and return an error naming the failing stage and the failing asset or parameter.
6. IF an export is requested for a timeline containing zero media segments, THEN THE Export_Coordinator SHALL reject the request before encoding begins, create no file at the requested output path, and return an error stating that the timeline is empty.
7. WHEN a user cancels a running export, THE Export_Coordinator SHALL stop encoding within 2 seconds of the cancellation, delete the partially written output file so that no file remains at the requested path, report the export as cancelled, and report the project as unmodified.
8. FOR ALL fixed timelines of up to 3600 frames, export requests and encoder selections, two successive exports SHALL produce identical frame counts and identical per-frame presentation timestamps (determinism property).
9. IF an export request supplies an output path longer than 4096 characters, a parent directory that does not exist or is not writable, a container format or video codec that the Encoder_Selector does not support, or a resolution, frame rate or bit rate outside the ranges stated in criterion 1, THEN THE Export_Coordinator SHALL reject the request before encoding begins, create no file at the requested path, and return an error naming the rejected parameter together with its accepted range or supported values.
10. IF an export is requested through the export dialog or the `timeline.export` tool while another export is running, THEN THE Export_Coordinator SHALL reject the new request, leave the running export and its progress reporting unaffected, and return an error stating that an export is already in progress.
11. IF an export request targets a path at which a file already exists and the request carries no explicit overwrite acknowledgement, THEN THE Export_Coordinator SHALL reject the request before encoding begins, preserve the existing file byte-for-byte, and return an error stating that the destination already exists.

### Requirement 8: GPU-Accelerated Encoding with CPU Fallback

**User Story:** As an editor with a discrete GPU, I want exports to use hardware encoding, so that renders finish faster while still working on machines without a supported GPU.

#### Acceptance Criteria

1. WHERE `PALMIER_ENABLE_NVENC`, `PALMIER_ENABLE_QSV` or `PALMIER_ENABLE_VAAPI` is ON (each defaults to ON) AND the corresponding vendor SDK/driver development package is found by dependency detection at configure time, THE build SHALL define the matching `PALMIER_HAVE_NVENC`, `PALMIER_HAVE_QSV` or `PALMIER_HAVE_VAAPI` compile definition for the gpu and media targets and SHALL list that path as enabled in the CMake configuration summary.
2. WHEN an export request specifies hardware encoding for one of the three supported codecs (H.264, HEVC, VP9) AND the corresponding hardware encode path is compiled in AND the device-capability probe reports a device and driver that support that codec, THE Encoder_Selector SHALL select the vendor hardware encoder for that codec and SHALL report exactly one selected encoder name in the export result together with a software-fallback flag set to false.
3. IF initialization of the selected hardware encoder fails before the first frame is encoded, THEN THE Encoder_Selector SHALL retry hardware initialization no more than once, SHALL select the software encoder for the same codec with the requested resolution, frame rate and bit rate unchanged, SHALL complete the export with the same frame count as the requested range, and SHALL report in the export result the selected software encoder name plus a software-fallback flag set to true with a reason indicating hardware encoder initialization failure.
4. WHERE no hardware encode path is compiled in, OR the device-capability probe reports no codec-compatible device, OR the probe does not return within 3000 ms of starting, THE Encoder_Selector SHALL select the software encoder (`libx264` for H.264, `libx265` for HEVC, `libvpx-vp9` for VP9) and complete the export.
5. THE L4_Validation_Job SHALL export the fixture timeline of at least 300 frames at 1920x1080 and 30 frames per second on an NVIDIA L4 device using `h264_nvenc` and SHALL record, as job output, the selected encoder name, the elapsed wall-clock time in milliseconds and the output file size in bytes.
6. WHEN the same fixture timeline (at least 300 frames, 1920x1080, 30 frames per second) is exported once with hardware encoding and once with software encoding, THE Export_Coordinator SHALL produce two decodable outputs whose frame counts are both equal to the fixture frame count and whose durations differ by no more than one frame interval (1/30 s, approximately 33.4 ms).
7. THE Composition_Root SHALL expose a public accessor that reports, for each of the VAAPI, NVENC/NVDEC, QSV and FFmpeg software backends, one compiled-in boolean and one usable-on-current-host boolean, SHALL always report the FFmpeg software backend as both compiled in and usable, and SHALL return the report within 3000 ms without changing any encoder selection or export state.
8. FOR ALL combinations of the three supported codecs (H.264, HEVC, VP9) and the eight compiled-in states of the VAAPI, NVENC and QSV paths, THE Encoder_Selector SHALL return exactly one encoder selection, SHALL set the software-fallback flag to true only when the returned selection is a software encoder, and SHALL never report both hardware use and software fallback for the same export (invariant property).
9. IF a vendor path is enabled at configure time but its SDK/driver development package is not found, THEN THE build SHALL complete configuration successfully, SHALL leave that path's `PALMIER_HAVE_*` compile definition undefined, and SHALL list that path as disabled in the CMake configuration summary.
10. IF the L4_Validation_Job records a selected encoder other than `h264_nvenc`, a software-fallback flag of true, or an output file size of 0 bytes, THEN THE L4_Validation_Job SHALL exit with a failure status and SHALL retain the recorded measurements as job output.
11. IF the hardware encoder fails after at least one frame has been encoded, THEN THE Export_Coordinator SHALL stop the export, SHALL delete the incomplete output file, SHALL report an error indicating a mid-export hardware encode failure, and SHALL leave the open project unmodified.


### Requirement 9: MCP Standards Compliance

**User Story:** As an agent user, I want to connect Claude Code, Codex or Cursor to the editor with their standard MCP configuration, so that no custom client adapter is needed.

#### Acceptance Criteria

1. WHEN the MCP_Endpoint receives a POST request on `/mcp` whose body is a JSON-RPC 2.0 request of at most 1 MiB, THE MCP_Protocol_Handler SHALL respond within 1000 milliseconds with a JSON-RPC 2.0 response object that carries `"jsonrpc":"2.0"`, carries the request `id` unchanged, and carries exactly one of `result` or `error`.
2. WHEN the MCP_Protocol_Handler receives the `initialize` method, THE MCP_Protocol_Handler SHALL return a negotiated protocol version equal to the client-requested version when that version is one the MCP_Protocol_Handler supports and otherwise equal to the highest version it supports, a non-empty server name, a server version, and a capabilities object that declares the `tools` capability.
3. WHEN the MCP_Protocol_Handler receives the `tools/list` method, THE MCP_Protocol_Handler SHALL return one entry per tool registered in the Tool_Surface — so that the entry count equals the Tool_Surface tool count — with each entry containing a non-empty `name` of at most 64 characters, a non-empty `description`, and an `inputSchema` object that is a JSON Schema of type object naming each accepted argument and listing the required arguments.
4. WHEN the MCP_Protocol_Handler receives the `tools/call` method with a tool name registered in the Tool_Surface and an arguments object that validates against that tool's advertised `inputSchema`, THE MCP_Protocol_Handler SHALL execute the tool through the same execution policy used for GUI and in-app agent invocations — argument validation, rollback on failure, and undo-history recording — and return a result object containing a `content` array whose first entry has `"type":"text"`, plus `isError` set to false.
5. IF a tool invoked through `tools/call` fails, THEN THE MCP_Protocol_Handler SHALL return a JSON-RPC result with `isError` set to true and a `content` entry naming the failing tool and the failure reason, and SHALL leave the project — its track count, clip set, clip source ranges, effects, transitions, asset references and undo history — in its pre-invocation state.
6. IF a request body is not parsable JSON, or exceeds 1 MiB, THEN THE MCP_Protocol_Handler SHALL respond with JSON-RPC error code -32700 and SHALL create no edit command.
7. IF a request is not a valid JSON-RPC 2.0 request object — because it omits `"jsonrpc":"2.0"`, omits `method`, or supplies `method` or `id` with a JSON type other than string (or, for `id`, number or null) — THEN THE MCP_Protocol_Handler SHALL respond with JSON-RPC error code -32600.
8. IF a request names a method other than `initialize`, `notifications/initialized`, `tools/list` or `tools/call`, THEN THE MCP_Protocol_Handler SHALL respond with JSON-RPC error code -32601 and an error message naming the unsupported method.
9. IF a `tools/call` request names a tool absent from the Tool_Surface, omits a required argument, supplies an argument of the wrong JSON type, or supplies an argument value outside the bounds declared by the tool's `inputSchema`, THEN THE MCP_Protocol_Handler SHALL respond with JSON-RPC error code -32602 naming the offending tool or argument, SHALL create no edit command, and SHALL leave the project state unchanged.
10. WHEN the MCP_Protocol_Handler receives the `notifications/initialized` notification, THE MCP_Protocol_Handler SHALL accept it, send a response body of zero bytes, answer with HTTP status 202 within 1000 milliseconds, and treat the session as initialized.
11. WHEN a client completes `initialize`, THE MCP_Endpoint SHALL return a session identifier header whose value is an opaque string of at least 32 characters that is unique among all sessions active since application start, and SHALL accept that identifier on subsequent requests from the same client until the session is closed or expires.
12. FOR ALL tools in the Tool_Surface, the `tools/list` entry SHALL declare a schema that accepts the arguments the tool's own handler accepts and rejects arguments the handler rejects (schema conformance property).
13. FOR ALL well-formed JSON-RPC requests that carry an `id`, THE MCP_Protocol_Handler SHALL produce a response that parses as JSON and echoes the request `id` unchanged in both type and value; FOR ALL well-formed notifications, which carry no `id`, THE MCP_Protocol_Handler SHALL produce no response body (round-trip property).
14. IF a `tools/list` or `tools/call` request arrives on a session that has not completed `initialize`, THEN THE MCP_Protocol_Handler SHALL respond with a JSON-RPC error indicating that the session is not initialized, SHALL create no edit command, and SHALL leave the project state unchanged.
15. IF a request presents a session identifier that the MCP_Endpoint does not recognise or that has expired, THEN THE MCP_Endpoint SHALL reject the request with an error indicating that the client must repeat `initialize`, and SHALL create no edit command.
16. IF a tool invoked through `tools/call` does not complete within 60 seconds, THEN THE MCP_Protocol_Handler SHALL abandon the invocation, return a result with `isError` set to true and a `content` entry naming the tool and stating that it exceeded the execution time limit, and SHALL leave the project in its pre-invocation state.

### Requirement 10: Secure Remote MCP Access

**User Story:** As a user running the editor on a remote workstation, I want to connect an agent from another machine without an SSH tunnel, so that I can drive the editor from my laptop while keeping the endpoint secure.

#### Acceptance Criteria

1. WHEN the application starts without explicit remote-access configuration, THE MCP_Endpoint SHALL bind only the loopback address `127.0.0.1` on port 19789 and SHALL refuse every connection whose source address is not a loopback address.
2. WHERE remote access is enabled by configuration, THE Remote_Access_Gate SHALL require all three of the following before the MCP_Endpoint binds a non-loopback address: a bind address that is a syntactically valid IPv4 or IPv6 literal, a bearer token of 32 to 512 printable ASCII characters, and an acknowledgement flag explicitly set to true.
3. IF remote access is enabled while any of the three prerequisites in criterion 2 is absent or outside the stated bounds, THEN THE Remote_Access_Gate SHALL refuse to bind a non-loopback address, SHALL bind `127.0.0.1` on port 19789 instead, and SHALL emit a startup error naming each unmet prerequisite without including the configured token value.
4. WHILE the MCP_Endpoint is bound to a non-loopback address, THE Remote_Access_Gate SHALL reject any request whose `Authorization` header is absent, malformed, or not byte-identical to the configured bearer token with HTTP status 401 within 500 milliseconds of receipt, and SHALL NOT dispatch that request to the Tool_Surface.
5. WHILE the MCP_Endpoint is bound to a non-loopback address, THE Remote_Access_Gate SHALL reject requests whose `Origin` header is present and names a host outside the configured allow-list with HTTP status 403 and SHALL NOT dispatch that request to the Tool_Surface, treating an unconfigured allow-list as empty so that only the bound address and loopback hosts are accepted.
6. WHERE a TLS certificate and private key are configured, THE MCP_Endpoint SHALL serve HTTPS on the configured address and SHALL reject any plaintext HTTP request on that port without dispatching it to the Tool_Surface.
7. IF remote access is enabled without TLS configured, THEN THE Remote_Access_Gate SHALL emit exactly one startup warning to the application log, before the first request is accepted, stating that traffic is unencrypted and recommending a tunnel or TLS, and SHALL still complete the configured non-loopback bind.
8. WHEN a request is rejected by the Remote_Access_Gate, THE Remote_Access_Gate SHALL record, within 1 second of the rejection, the UTC timestamp with millisecond precision, the source address and the rejection reason in the application log, and SHALL exclude the presented token value and every substring of it from that record.
9. THE Remote_Access_Gate SHALL limit concurrent MCP sessions to a configurable maximum in the range 1 to 32 with a default of 8, and IF a session-initiating request arrives while that maximum is reached, THEN THE Remote_Access_Gate SHALL reject only that request with an error indicating the session limit was reached and SHALL keep all established sessions active.
10. FOR ALL request sequences on a loopback-only configuration, THE Remote_Access_Gate SHALL accept requests that carry neither an `Authorization` header nor an `Origin` header, without issuing HTTP status 401 or 403, and preserve the current default developer experience (compatibility property).
11. WHILE an established MCP session has received no request for longer than the configured idle timeout, which is configurable in the range 30 to 3600 seconds with a default of 300 seconds, THE Remote_Access_Gate SHALL close that session, record the closure reason, and reject subsequent requests carrying that session identifier with an error indicating the session is no longer valid.
12. IF remote access is enabled and the configured TLS certificate or private key cannot be read, cannot be parsed, or does not form a matching pair, THEN THE Remote_Access_Gate SHALL refuse to bind a non-loopback address, SHALL bind `127.0.0.1` on port 19789 instead, and SHALL emit a startup error indicating which of those three conditions occurred.
13. IF 5 consecutive requests from the same source address are rejected with HTTP status 401 within any 60-second window, THEN THE Remote_Access_Gate SHALL reject all further requests from that source address with HTTP status 401 for the next 60 seconds, SHALL record each such rejection per criterion 8, and SHALL continue serving requests from all other source addresses.

### Requirement 11: Pluggable Agent Reasoning

**User Story:** As a user of the in-app agent, I want to type a request in plain language and have the editor act on it, so that I do not need to know tool names.

#### Acceptance Criteria

1. THE Composition_Root SHALL accept exactly one Agent_Interpreter implementation through configuration, SHALL expose the active implementation through a public accessor, and SHALL route every in-app agent utterance through that implementation.
2. WHERE an authenticated hosted account or BYOK credentials that the account service reports as present and unexpired are configured, WHEN a user submits an utterance of 1 to 2000 characters, THE Agent_Interpreter SHALL return, within 30 seconds, exactly one tool name that exists in the Tool_Surface together with an argument object that satisfies that tool's declared input schema.
3. WHERE no hosted account and no BYOK credentials are present, THE Agent_Interpreter SHALL use a built-in offline interpreter that maps a documented set of at least 10 command phrases (for example "split the clip at the playhead", "mute track 2", "export as mp4") to tool invocations in Offline_Mode, matching phrases without regard to letter case or leading and trailing whitespace, returning a mapping within 1 second, and issuing no network request.
4. IF an utterance cannot be mapped to a tool in the Tool_Surface, THEN THE Agent_Interpreter SHALL return a message that quotes the unrecognised request, SHALL invoke no tool, and SHALL leave the project state and the undo history depth unchanged.
5. WHEN the Agent_Interpreter produces a tool invocation, THE Tool_Surface SHALL execute it through the same execution policy the MCP_Protocol_Handler uses, validating the arguments before execution, restoring the pre-invocation project state if execution fails, and recording exactly one undo entry when execution succeeds.
6. WHEN an agent utterance references media with an `@` mention that names exactly one asset in the project media library, THE Agent_Interpreter SHALL substitute that asset's identifier into the tool arguments before the tool is executed.
7. IF an `@` mention in an utterance matches no asset or more than one asset in the project media library, THEN THE Agent_Interpreter SHALL return an error that names the mention text and the number of matching assets, SHALL invoke no tool, and SHALL leave the project unchanged.
8. IF the configured Agent_Interpreter reports a credential or backend failure, or returns no mapping within 30 seconds, THEN THE Agent_Interpreter SHALL return an error naming the failure reason, SHALL invoke no tool, and SHALL leave the project unchanged.
9. IF a submitted utterance is empty after whitespace removal or exceeds 2000 characters, THEN THE Agent_Interpreter SHALL reject it with an error stating the permitted length range and SHALL invoke no tool.
10. FOR ALL utterances the offline interpreter maps successfully, executing the produced invocation SHALL yield the same project state and the same undo history depth as invoking that tool directly with the same arguments (equivalence property).
